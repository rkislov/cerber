# Endpoint policies, active response and local IOC scans

Enable the server with its existing `-patch-key` signing key and optional encrypted integration settings. A separate private `CONTROL_DB.endpoint.db` stores policies, assignments, desired blocks, endpoint reports and the decision audit. Include it in state backups. Agents opt in with absolute `endpoint_state` and `endpoint_key` paths in their root/Administrator-owned config. The trusted Ed25519 public key must be installed locally; it is never downloaded from the command channel. Linux root / Windows LocalSystem privileges are required for firewall operations and a full local file scan.

The **Политики и реагирование** console section has server, workstation and future mobile profiles, explicit active-response enablement, training/confirmation modes, file-scan settings, protected addresses, exclusions and group/agent assignments. Only named administrators may mutate them; normal console authentication, origin and CSRF checks apply. Group assignments currently snapshot the group's membership when saving; save again after changing membership. Each agent can have one policy; move it by first removing its old assignment. Existing inventory/update schedules remain in Jobs. Mobile profiles reserve configuration only; enabling execution requires an Android/iOS agent or MDM integration and is rejected today.

Modes:
- Off: no firewall commands.
- Learning: recent correlation detections generate logged proposals, deduplicated by agent/IP/rule/day. They never become commands. The learning loop currently examines the latest 100 detections per 30-second pass, so a high-volume burst may require reviewing detections directly.
- Confirmation: blocks require a separate administrator submission with exact IP, agent, reason and TTL (1–1440 minutes). There is no automatic blocking. Special addresses, managed-agent addresses, resolved SIEM console addresses and policy exclusions are protected. Cancellation is a separately audited desired-state change.

The authenticated agent exchange delivers signed, agent-bound, expiring policies and block state, plus a versioned complete IOC cache when required. The agent verifies signature, identity, expiry, monotonic issue time and IOC digest before use. The public key, state directory and local configuration must be protected from unprivileged modification. Policy responses expire after 24 hours; scanning pauses when authorization expires. Network outages preserve the previous valid cache and do not stop local expiry reconciliation. Server state is a request, not evidence of successful application: agent results are shown separately.

Linux adds only `inet cerber_ar_ID` tables with timed IPv4/IPv6 sets and input/output DROP rules. It never flushes or changes existing firewall tables. Native kernel timeouts expire the block without agent/server connectivity; agent cleanup removes empty tables. Windows uses dedicated `CerberAR_ID` rules and a SYSTEM scheduled expiration task with StartWhenAvailable. The task is registered before adding rules; agent restart also reconciles expiry/cancellation. Windows behavior must be validated on a real Windows host before production rollout there. Errors remain visible as apply_failed / rollback_failed; cancellation is acknowledged on the next agent exchange, normally within about a minute.

File checks enumerate local disks, excluding virtual/network mounts and symbolic links. They read regular files only, compare SHA-256/MD5 with centrally imported ThreatFox hashes, and never delete/quarantine files. A batch reads at most 300 files / about 512 MiB / 10 seconds, files over 128 MiB are skipped and counted. Windows junctions/reparse links are excluded. Linux mounting metadata failure disables traversal rather than scanning network mounts accidentally. Large directories and inaccessible files can delay or limit coverage; reports distinguish partial/completed and count skips. The cursor resumes between batches. File contents remain local; only a matching path, hashes and IOC evidence are delivered. These typed source records are stored in the SIEM and revalidated by central IOC correlation. Cache refresh and scan schedules are policy settings; the first cycle has a configured UTC hour, shown as Moscow time in the UI. Subsequent cycles use the configured interval after completion.

Dashboard IOC counts separately show imported indicators, unique IPs, IP:port indicators, domains, URLs and file hashes, with last full import and sync/scan errors. These differ from managed-agent IP/subnet counts.

Private IPs may be blocked when explicitly confirmed and absent from protected addresses; the local policy can protect entire private CIDRs when required. Local passive network IOC matching uses the verified cached index, expires with signed authorization, and reports a match counter; original events remain on the normal durable source queue for central revalidation. It never triggers an autonomous block.
