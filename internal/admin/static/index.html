Правила Suricata

Центральный каталог · ET Open и собственные правила

+ Собственные правила

SID должны быть уникальными, rev — положительным. Скрипты и внешние файлы данных не поддерживаются. Базовый пакет и собственные правила сохраняются как новая объединённая версия.

Подключение движка и ключ проверки пакетов

В локальной конфигурации сенсора настройте suricata: directory, binary, yaml, socket и public_key. Запущенный движок должен использовать единственный rule-files: абсолютный путь к active.rules в этом каталоге. Настройка захвата трафика остаётся локальной.

Каталог ограничен 12 версиями и 64 МиБ сжатых пакетов. Удаляйте ненужные версии; назначенные, применённые и резервные версии защищены.

Сетевые сенсоры

Пассивный приём событий и потоков · состояние обновляется раз в минуту

Сенсор проверяет подпись и целостность, запускает suricata -T, затем перезагружает правила. При ошибке применения восстанавливается предыдущий файл. Чтение EVE и доставка событий продолжаются независимо.

История назначений и применения

История и оповещения

Пропуски означают отсутствие достоверного замера. Очередь — максимум за интервал для всего сенсора. Счётчики отражают сообщения, дошедшие до процесса; потери в сети не измеряются. До 200 000 агрегатов на сервер: при достижении лимита старейшие удаляются раньше срока.

Оповещения сенсора

Ожидаемые экспортёры

Добавьте только источники с регулярным экспортом. Пустой IP означает любой разрешённый экспортёр входа. Минимальный период тишины — 3 минуты; удалённые и приостановленные входы не проверяются.

Предупреждения появляются в разделе «Предупреждения», почта отправляется через сохранённый SMTP. Повторные проверки не создают копии открытого предупреждения; при восстановлении оно закрывается автоматически. Ошибки оцениваются по полным минутам. Порог заполнения очереди и ошибка применения конфигурации проверяются сразу.

UDP не подтверждает доставку: счётчики отражают только сообщения, дошедшие до процесса. Список содержит до 8 последних сеансов экспортёров на вход; IP и domain из UDP не удостоверяют устройство. Ошибки здесь относятся к приёму и разбору на сенсоре; результаты нормализации доступны в журнале событий SIEM.

Изменения применяются при следующем обмене с сервером, без перезапуска. При занятом порте действующие входы сохраняются. Удаление закрывает сокет; пауза только отбрасывает новые пакеты. Очередь доставки сохраняется. Адрес должен принадлежать сенсору: 0.0.0.0 или :: открывают вход на всех интерфейсах соответствующей семьи. Правила firewall автоматически не меняются. Для NetFlow v9/IPFIX изменённый вход ожидает повторную отправку шаблонов.

Журнал решений

Подсети и расписания

Любой размер CIDR: до 256 адресов за запуск, следующие окна — по расписанию. Время отображается в часовом поясе браузера.

Сканируйте только разрешённые сети. На агенте требуется Nmap. Проверки: MS17-010, Heartbleed, POODLE, CCS Injection, MS15-034; сведения о версиях не подтверждают CVE. Закрытые или фильтруемые узлы могут не обнаруживаться.

Карта сети и активов

Цвет и числа показывают записи об уязвимостях, включая кандидатов по версии; подтверждение указано в карточке. Группировка по области сканирования, а не физическая топология. IP идентифицирует наблюдение внутри плана; DHCP может менять владельца адреса.

Интеграции: почта, ThreatFox и AD

Доступно только именованным администраторам. Секреты хранятся зашифрованными и не возвращаются в браузер.

Почтовый сервер SMTP

ThreatFox · abuse.ch

Пустые поля секретов сохраняют текущие значения. Настройки SMTP и ThreatFox сохраняются отдельно. Первичная и последующие синхронизации загружают полный актуальный экспорт, включая IP-адреса. Обновление каждый час; после смены набора сохранённые события проверяются заново. Почта: предупреждения и срабатывания корреляций, очередь и повторные попытки.

AD / LDAPS · проверка участников цепочки

Только чтение каталога. Этот раздел не назначает права входа в SIEM. DNS/NetBIOS-имена подтверждаются по crossRef; пользователи — по SID и objectGUID. Base DN должен быть корнем домена контроллера. Другие домены и LDAP referrals автоматически не обходятся.

Проверка TLS обязательна. Кеш успешной проверки — до 5 минут; ошибки связи — 1 минута. Во время сбоя сохраняется сопоставление по точным исходным именам, без объединения алиасов. Изменение настроек сбрасывает доверие к старому кешу. Старые срабатывания не пересчитываются автоматически; проверка правила использует текущий каталог.

ХРАНЕНИЕ СОБЫТИЙ
Сроки хранения и архивы
События переносятся только после обработки. Доказательства всех срабатываний остаются в оперативном журнале. Новые сроки действуют и для уже сохранённых данных. Истёкшие архивы удаляются без возможности восстановления средствами Cerber.
Одна партия — до 250 событий и около 8 МиБ исходных данных. При наличии старых событий партии выполняются с паузой 1 секунда, иначе — раз в минуту. Файлы JSONL.gz проверяются по SHA-256 перед переносом и при скачивании. WAL регулярно проходит checkpoint; свободные страницы SQLite используются повторно. Полный VACUUM работающей БД не запускается. Лимиты приостанавливают приём новых событий, сохраняя их в очередях агентов. Бессрочные архивы не удаляются при достижении бюджета. Другие службы тоже расходуют место: для долгосрочного хранения используйте отдельный том.
