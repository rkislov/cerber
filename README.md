# Cerber

Cerber — проект платформы мониторинга безопасности и управления уязвимостями сети.
Первый этап — сканер операционных систем с локальным и сетевым режимами работы.

Автор: **Кислов Роман Сергеевич**. Лицензия: [Apache 2.0](LICENSE).

## Текущее состояние

Реализован первый CLI-прототип на **Go**:

- Добавление и просмотр активов с IPv4/IPv6; создание целей из зарегистрированных активов.
- Создание задач со снимком адресов и параметров сканирования.
- TCP connect-проверки с ограничением параллелизма, таймаутом и отменой через Ctrl+C.
- SQLite-хранилище, история задач и результатов между запусками.
- Транзакционный outbox событий с версионированным envelope и чтением по курсору.

Открытый порт — наблюдение о доступности сервиса, а не подтверждённая уязвимость.
Импорт записей БДУ/NVD в модель уязвимостей, matching, SSH/SMB/WMI, GUI, расписания, роли,
API управления сканером и SIEM-корреляция ещё не реализованы. Репозиторий пакетов БДУ описан ниже.

## Быстрый запуск

Требуется Go 1.25+ с автоматическим выбором toolchain: в `go.mod` закреплён Go 1.26.9.
При отключённой автозагрузке установите Go 1.26.9 или новее вручную. CGO не требуется.

```sh
go build -o bin/cerber ./cmd/cerber
./bin/cerber asset add -ip 127.0.0.1 -name localhost
./bin/cerber asset list
```

Подставьте ID из вывода предыдущих команд:

```sh
./bin/cerber target add -name local -assets ASSET_ID
./bin/cerber task create -target TARGET_ID -ports 22,80,443 -concurrency 16 -timeout-ms 1000
./bin/cerber task run -id TASK_ID
./bin/cerber task show -id TASK_ID
./bin/cerber events list -after 0 -limit 100
```

Вывод — JSON. `task run` выполняется синхронно; Ctrl+C сохраняет завершённые проверки
и переводит задачу в `interrupted`. Ошибка соединения записывается отдельно от отказа
в соединении и таймаута. Ошибка записи останавливает выполнение задачи.
Повторный запуск той же задачи запрещён; для нового сканирования создайте новую задачу.

База по умолчанию: `.local/cerber.db`. Общий параметр `-db PATH` указывается **перед** командой:

```sh
./bin/cerber -db .local/demo.db asset list
```

Начальные ограничения одной задачи: 256 активов, 1024 порта, 65536 соединений,
64 одновременных соединения, таймаут 10–30000 мс. Поддерживаются явные IP-адреса
и списки портов; CIDR, DNS discovery и диапазоны портов будут добавлены отдельно.
Применяйте проверки к сетям, на сканирование которых у вас есть разрешение.

## Структура кода

- `internal/domain` — активы, цели, задачи, наблюдения и ограничения.
- `internal/ports` — интерфейсы хранилища, сканера и чтения событий.
- `internal/app` — сценарии приложения и жизненный цикл задачи.
- `internal/scanner/tcp` — ограниченный пул TCP-проверок.
- `internal/storage/sqlite` — SQL-адаптер, версия схемы и транзакционный outbox.
- `internal/event` — контракт событий продукта; независим от брокера и GUI.
- `internal/knowledge` — публикация подписанных XML-пакетов, HTTP-репозиторий и клиентский кэш.
- `cmd/cerber` — CLI, конфигурация и обработка сигналов.

Доменные данные и события фиксируются одной транзакцией. Это основа будущей
публикации событий с повторной доставкой; сетевой publisher пока отсутствует.
Каждый потребитель сможет хранить собственный курсор. Outbox не является готовым
хранилищем высокочастотных журналов SIEM и пока не очищается автоматически.

Целевая серверная архитектура разделяет сбор, обработку, хранение и корреляцию.
PostgreSQL предназначен для управляющих данных, ClickHouse — для оперативных событий,
объектное хранилище — для архива. Эти адаптеры пока не подключены.
`KnowledgeProvider` обеспечивает проверенный локальный снимок базы перед стартом задачи.
ID, версия и SHA-256 фиксируются вместе с переходом в `running` и событием старта.
TCP-проверки могут работать без базы знаний. SQLite поддерживает миграцию схемы
с сохранением прежних данных.

Desktop-клиент будет использовать то же ядро через адаптер; выбор оболочки после перехода
на Go остаётся открытым. В перспективе: сбор событий, поиск, корреляция и обработка инцидентов.

## Проверка и платформы

```sh
go test -race ./...
go vet ./...
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -o bin/cerber-linux-arm64 ./cmd/cerber
```

Целевые платформы: Windows x86_64, Linux x86_64/aarch64. Кросс-сборка не заменяет
проверку запуска на целевой ОС. Установщики пока не выпускаются.

При SIGKILL, отключении питания или падении процесса задача может остаться в `running`.
Автоматическое восстановление и leases ещё не реализованы; не меняйте статус такой задачи,
пока не установлено, что исполнитель остановлен. Полноценного фонового планировщика нет:
параллельно запущенные CLI-процессы имеют отдельные лимиты соединений.

Уведомления о лицензиях зависимостей: [THIRD_PARTY_NOTICES.txt](THIRD_PARTY_NOTICES.txt).

## Централизованный репозиторий БДУ

Сервер публикует исходный XML как неизменяемый пакет. На этом этапе проверяется
структурная корректность XML (UTF-8, без DTD), размер и SHA-256; разбор полей БДУ
и проверка схемы конкретной выгрузки ещё не реализованы. Подпись Ed25519 принадлежит
издателю Cerber и не является подписью ФСТЭК. Сохраняется provenance: адрес загрузки
или признак офлайн-импорта.

Подготовка на сервере:

```sh
./bin/cerber knowledge keygen -dir .local/knowledge-keys
./bin/cerber knowledge publish -file /path/to/vulxml.xml -version 2026-10-19.1 -private-key .local/knowledge-keys/signing.key
```

Вместо файла можно указать `-url HTTPS_URL`: выгрузка будет загружена централизованно
и опубликована после проверки. HTTP-редиректы при загрузке запрещены.
Каждая публикация требует новой версии; сервер присваивает возрастающий номер последовательности.
Обновление пока запускается вручную, автоматического ежедневного расписания нет.

Передайте `signing.pub` исполнителю по доверенному каналу. Закрытый `signing.key`
остаётся у издателя; HTTP-серверу он не нужен. Установите одинаковый случайный токен
длиной от 24 символов в `CERBER_KNOWLEDGE_TOKEN` на сервере и исполнителе.
Токен не передаётся аргументом командной строки.

```sh
# Сервер: команда работает до Ctrl+C.
./bin/cerber knowledge serve -listen 127.0.0.1:8787

# Исполнитель, в другом терминале с тем же токеном:
./bin/cerber knowledge sync -server http://127.0.0.1:8787 -public-key /path/to/signing.pub
./bin/cerber task run -id TASK_ID -knowledge-server http://127.0.0.1:8787 -knowledge-key /path/to/signing.pub
```

Второй запуск проверяет свежий манифест и хеш кэша, повторно XML не скачивает.
Новая версия с тем же содержимым также использует уже проверенный файл.
Кэш содержит XML по SHA-256, подписанные манифесты версий и активный манифест.
Подмена подписи, содержимого, повторное использование версии и откат последовательности
отклоняются. Защита от отката опирается на сохранённое локальное состояние после первой
успешной синхронизации; кэш и доверенный ключ должны быть защищены от локальной подмены.
Ротация ключей и автоматическая очистка старых версий пока не реализованы.

Офлайн-режим включается явно:

```sh
./bin/cerber knowledge sync -offline -public-key /path/to/signing.pub
./bin/cerber task run -id TASK_ID -knowledge-offline -knowledge-key /path/to/signing.pub
```

По умолчанию максимальный возраст **манифеста публикации** — 72 часа, настраивается
`-max-age` у `knowledge sync` и `-knowledge-max-age` у `task run`. Это не возраст записей
БДУ и не гарантия актуальности исходной выгрузки. Офлайн-режим сохраняет проверку возраста.
При ошибке получения или проверки снимка задача остаётся в очереди; тихого перехода
с онлайн-режима на старый кэш нет. Кэш меняется только после проверки полного пакета.

Для доступа по сети используйте HTTPS с доверенным сертификатом:

```sh
./bin/cerber knowledge serve -listen 0.0.0.0:8787 -tls-cert /path/to/server.crt -tls-key /path/to/server.key
```

Plain HTTP разрешён только на явных loopback IP; в том числе клиент не принимает
`http://localhost` или сетевой HTTP-адрес. Альтернатива — TLS reverse proxy перед loopback-сервером.
Read-only API: `GET /v1/knowledge/latest` и `GET /v1/knowledge/packages/{sha256}`;
оба требуют `Authorization: Bearer ...`. Публикация выполняется локальной CLI-командой,
HTTP-загрузки пакетов на сервер нет. Максимум пакета — 512 MiB, манифеста — 64 KiB.

Одновременная запись в один репозиторий или кэш блокируется каталогом `.write-lock`.
После аварийного завершения он может сохраниться: удаляйте его только после проверки,
что предыдущий процесс остановлен. Объекты сначала записываются во временные файлы,
проверяются и синхронизируются, затем переименовываются. Это не заменяет резервное
копирование, и гарантии при потере питания зависят от ОС и файловой системы.
